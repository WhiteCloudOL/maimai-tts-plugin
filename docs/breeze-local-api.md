# BreezeTTS 本地API配置

插件的「BreezeTTS → 本地API」使用 Breeze-TTS-2.cpp 原生 HTTP 接口，支持下面两个服务端：

| 项目 | 接入特点 | BaseURL 示例 |
| --- | --- | --- |
| [HoppouAI/Breeze-TTS-2.cpp](https://github.com/HoppouAI/Breeze-TTS-2.cpp) | GGUF 推理、服务端音色库、原生表单与 PCM 流 | `http://127.0.0.1:8080/v1` |
| [WhiteCloudOL/Breeze-TTS-2.cpp](https://github.com/WhiteCloudOL/Breeze-TTS-2.cpp) | Bearer 鉴权、FIFO 排队，沿用相同合成与音色接口 | `http://127.0.0.1:7863/v1` |

## 1. 平台连接

1. 添加 BreezeTTS 服务商，接入方式选择「本地API」。
2. BaseURL 填写服务端地址及 `/v1`，例如 `http://127.0.0.1:7863/v1`。
3. 使用鉴权版时，在 API Key 中填写服务端配置的一把有效密钥。插件自动添加 `Authorization: Bearer <密钥>`。
4. 添加 `breeze-tts-2` 模型。模型标识用于插件路由与配置管理，服务端实际使用启动时加载的 GGUF。
5. 在整体语音路由中选用这个服务商与模型。

原版可使用空 API Key。fork 的多把密钥由服务端统一配置，插件在每次合成、音色同步及音色管理请求中发送平台保存的那一把密钥。

WhiteCloudOL fork 的 Windows 启动脚本默认使用鉴权端口 `7863`，原版入口使用 `7865`。端口以实际启动参数为准。

## 2. 声音来源

### 服务端已保存音色

进入「音色与克隆 → 服务端音色」，点击「同步平台音色」，选择并保存已有音色。也可以在模型参数中选择「服务端已保存音色 ID」，直接填写 ID。

合成时插件将 ID 放入原生表单的 `voice_id`。模型、音色和本次调用的风格描述按现有继承规则组合，服务端使用保存的参考声音生成新语音。

### 动态参考录音

模型参数中的「参考录音」，或音色窗口中的「参考音色 → 动态参考录音」，可以保存录音路径、公开 URL 和准确文字稿。

插件读取 MP3 / WAV 录音，在工作线程中转换成 24 kHz 单声道 PCM16 WAV，再使用 `ref_audio` 与 `ref_text` 上传。每次读取实际参考录音，适合持续调整录音的工作流。

### 创建服务端音色

在「参考音色」中选择「创建服务端音色，保存音色 ID」，填写显示名称、录音和完整文字稿。服务端音色 ID 可填写 1–64 位字母、数字、下划线和连字符；留空时插件自动生成 ID。

创建完成后，服务端保存 `.breeze` 文件，插件收藏返回的 ID。显示名称通过服务端 `metadata.name` 保存，重新同步目录时可以恢复。填写已有 ID 可更新该服务端音色的参考声音。

「移除服务端缓存音色」调用服务端 DELETE 接口，移出运行中音色与插件收藏。服务端保留已保存的 `.breeze` 文件，并在重启时重新加载。

### 文字设计与原生声音

「声音设计」通过风格描述定义声音，并作为插件音色配置保存。模型参数也提供「文字设计声音」与「模型原生声音」选项。

## 3. 语调、事件与参数

普通动态语调、工具调用与概率语音 LLM 自适应共用 Breeze 表演提示。整段和局部自由语气提取为服务端 `instruction`，音频事件保留在朗读 `text` 中，聊天保留文字使用清理后的正文。

例如：

```text
[语气:轻声温柔][轻笑]你终于来了。[停顿][语气:认真而坚定]我们一起面对。
```

插件按局部语气分段，结合标点补齐区段间隔后拼接完整音频。返回的 PCM 按服务端响应头封装为 WAV；聊天发送再采用通用设置中的音频格式。

模型参数提供 CFG 指令强度和随机种子。「C++ 采样与长文参数」中可以分别设置：

| 插件参数 | 服务端字段 | 用法 |
| --- | --- | --- |
| `breeze_cpp_temperature` | `temperature` | 采样温度，0 沿用模型默认值 |
| `breeze_cpp_top_k` | `top_k` | 候选词数量，0 沿用模型默认值 |
| `breeze_cpp_top_p` | `top_p` | 累积采样概率，范围 0–1，0 沿用模型默认值 |
| `breeze_cpp_repetition_penalty` | `repetition_penalty` | 重复惩罚，0 沿用模型默认值 |
| `breeze_cpp_split_chars` | `split_chars` | 留空沿用服务端设置；0 使用整段生成；正整数指定分段字符数 |
| `breeze_cpp_max_new_tokens` | `max_new_tokens` | 每段音频帧上限，0 沿用模型默认值；每秒约 12.5 帧 |

CFG=1 使用基础引导。需要更强的语气和事件表现时，可以从 2–3 开始调整。朗读节奏通过风格描述控制。

其他插件可以通过 `tts_describe` 查询这些参数，通过 `tts_advanced.parameters` 临时覆盖。`voice_id` 选择器可直接填写服务端 ID，调用示例见[插件 API 对接说明](plugin-api.md)。

## 4. 排队、超时与缓存

插件按服务实例依次提交合成和参考录音编码。fork 会将来自其他客户端的任务一起放入服务端 FIFO 队列，等待空闲槽位后执行。原版在槽位已满时返回 HTTP 409，插件将状态和原因回传到调用方。

「运行限制 → 平台请求超时」覆盖本次等待和平台处理时间。存在其他客户端排队时，可按任务长度设置为 300 秒等合适预算；整条合成链沿用插件的 540 秒总预算。

取消任务会关闭当前客户端的等待或响应连接，释放插件的实例串行名额。fork 按自身调度规则移除断线的等待请求。

动态参考录音与服务端音色每次使用实际来源合成，音色更新后可以即时取得新的声音。原生声音与文字设计按正文、风格、CFG、种子及 C++ 参数区分合成缓存。合成缓存和发送去重分别管理，相同 API 请求编号继续复用该次执行结果与发送回执。

服务端接口依据：[原项目服务端文档](https://github.com/HoppouAI/Breeze-TTS-2.cpp/blob/main/docs/server.md)、[fork 的鉴权与排队说明](https://github.com/WhiteCloudOL/Breeze-TTS-2.cpp/blob/main/docs/windows-auth.md)。
